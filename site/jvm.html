Hello.java → javac → Hello.class → java

Inside the JVM

What happens between typing javac Hello.java and seeing “Hello, World!”, shown with the real file the compiler made.

  1. You write source, Hello.java: text a person can read.
  2. javac compiles it to Hello.class, a 417-byte class file. It runs unchanged on any JVM of version 21 or later.
  3. java starts a JVM, which loads the class, checks that it is safe, and runs it.
  4. The JIT compiler turns code that runs often into the processor’s own instructions while the program runs.

  2. 2The version bytes 4–7major 65: compiled for Java 21, so it needs Java 21 or later to run. Versions →
  3. 3The constant pool bytes 8–30028 entries: every name and piece of text the class uses, “Hello, World!” among them. Lesson 01 →

  5. 5The methods bytes 311–4062 methods; main is 9 bytes of bytecode. Read below ↓

1 The magic number bytes 0–3

The first four bytes of every class file are CA FE BA BE. A JVM that reads anything else refuses the file.

2 The version bytes 4–7

Minor 0, major 65. Major versions count up from 45 (Java 1.0 and 1.1), so 65 means Java 21, and an older JVM will not run the file. See Versions.

3 The constant pool bytes 8–300

28 entries: the class’s own name, java/lang/Object, System.out, println and the text “Hello, World!”. Instructions refer to them by number, like #13 below. At 293 of 417 bytes, the pool is most of the file.

4 The class header bytes 301–310

Who may use the class (public), its own name, its superclass (Object), and its interfaces and fields, of which Hello has none. Lesson 07 builds a class with fields.

5 The methods and their bytecode bytes 311–406

Hello has 2 methods: the constructor the compiler adds, and main. This is what javap -c Hello prints for main’s 9 bytes of bytecode. Each line is one instruction for the JVM, which is a stack machine: instructions push values onto a stack and take them off.

public static void main(java.lang.String[]);
    Code:
       0: getstatic     #7                  // Field java/lang/System.out:Ljava/io/PrintStream;
       3: ldc           #13                 // String Hello, World!
       5: invokevirtual #15                 // Method java/io/PrintStream.println:(Ljava/lang/String;)V
       8: return
  • getstatic pushes System.out, the object that prints.
  • ldc pushes the string “Hello, World!” from the constant pool.
  • invokevirtual calls println on them.
  • return ends main, and with it the program.

6 The attributes bytes 407–416

Extra facts about the class. Here there is one: SourceFile, naming Hello.java, which stack traces and debuggers use to point back at your code. A compiler can be told to leave it out. See Ecosystem.

Memory you do not free

Objects live on the heap. When nothing refers to an object any more, the garbage collector reclaims it; there is no free and no delete. The price is that you do not decide exactly when memory comes back.
