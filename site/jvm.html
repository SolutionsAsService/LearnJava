Hello.java → javac → Hello.class → java

Inside the JVM

What happens between typing javac Hello.java and seeing “Hello, World!”, shown with the real file the compiler made.

  1. You write source Hello.java: text a person can read.
  2. javac compiles it to Hello.class: 417 bytes of bytecode, the same on every machine.
  3. java starts a JVM, which loads the class, checks it is safe, and runs it.
  4. The JIT compiler turns code that runs often into the machine’s own instructions while the program runs.

The magic number and the version

The first four bytes of every class file are CA FE BA BE. A JVM that reads anything else refuses the file. The next four are the version: minor 0, major 65. Major versions count up from 45 (Java 1.1), so 65 means Java 21, and an older JVM will not run it.

The bytecode of main

This is what javap -c Hello prints for main. Each line is one instruction for the JVM, which is a stack machine: instructions push values onto a stack and take them off.

public static void main(java.lang.String[]);
    Code:
       0: getstatic     #7                  // Field java/lang/System.out:Ljava/io/PrintStream;
       3: ldc           #13                 // String Hello, World!
       5: invokevirtual #15                 // Method java/io/PrintStream.println:(Ljava/lang/String;)V
       8: return
  • getstatic pushes System.out, the object that prints.
  • ldc pushes the string “Hello, World!” from the constant pool.
  • invokevirtual calls println on them.
  • return ends main, and with it the program.

Memory you do not free

Objects live on the heap. When nothing refers to an object any more, the garbage collector reclaims it; there is no free and no delete. The price is that you do not decide exactly when memory comes back.
